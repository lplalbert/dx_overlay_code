# tools — 真实拍照/微信压缩验证链路

生成「待实拍」的水印图 + 一套验证脚本。核心问题:**水印经过真实拍照和微信压缩后,定位块还检不检得出。**

载体图默认读 `CARRIER_DIR` = `/data1/lpl/datasets/test`(3 张 1920×1080 桌面截图),
可用环境变量覆盖:

```bash
export DX_CARRIER_DIR=/path/to/your/carriers
```

其余资源都按仓库根解析,不写死绝对路径。

---

## `gen_real_capture_v2.py` — 生成 9 张待实拍图

每张图 = 载体截图 + 四角回字标 + 水印,**不加任何模拟噪声**(噪声由真实拍照/微信产生)。

- **顺序:先盖角标,再叠水印。** 水印压在标上,振幅完整,不被标遮挡。
- 角标 120×120,**四角贴死边缘不留缝**,样式取自 `qr_loc_mark.png`(仓库根)。
- 水印 `alpha=0.032`,`channel_mode='b'`,水印序列随机,**六位十进制写进文件名**。
- 输出 `vis/real_capture/`:9 张 PNG + `manifest.json` + `README.txt`。
  `manifest.json` 里每张图带 `wm_id` / 六位数字 / 4 个角标框 / 6 个 GT 定位框。

命名:`wm<六位十进制 wm_id>_c<载体序号>.png`,例如 `wm323972_c01.png`。

**已知代价:** 右下角标 (1800,960)-(1920,1080) 与定位块 #6 (1760,945)-(1920,1080) 重叠
**66.7%**。因为是先标后水印,#6 的水印振幅完整,但底下 2/3 的载体纹理变成黑白回字。
实测代价是置信度下降(#6 conf 0.36–0.91,兄弟块 0.66–0.97),命中率与未覆盖的 #2/#3 同级。

## `verify_and_detect_v2.py` — 角标校验 + vv2 检测

1. 角标 120×120、贴边、逐字节 = `qr_loc_mark.png` 缩放结果
2. 角标区域水印振幅完整(`max|Δ| ≈ 8`,与别处一致)→ 证明没被遮挡
3. 逐字节复现出图,与磁盘 PNG 比对
4. 跑 vv2(conf=0.25, native 尺度),报 6 个定位块各自 OK/MISS,重点看 #6

输出 `vis/real_capture/clean_detect_vv2.json`。

## `verify_tpl_equiv.py` — 模板 vs 9 张图等效性

A. 每张图能否用「其 `wm_id` 的模板」+「其载体(先盖标)」**逐字节复现**
B. 同载体 3 张图的 6 个定位块区域是否**逐字节相同**(定位块模板应恒定,不随 `wm_id` 变)
C. 不同 `wm_id` 的消息区模板是否不同(消息模板应随 ID 变)

结论:`vis/tpl/` 里的完整模板只是某一个 `wm_id` 的;公式/结构/α/条纹/定位块全数据集共享。

## `qa_wm_effect.py` — 水印效果 QA

查 6 件事:强度一致性、溢出/裁剪、舍入偏差、角标区域强度、色偏方向、纯色区可见性。

## `why_diff.py` — 「强度为什么不一致」根因

受控实验分离两个原因:

- **A(主因)** 融合是 `Δ = α·(wm − c)` 插值,不是固定幅度加性 → 幅度随载体明暗在 0–8 之间漂。
  中灰 c=128 只有 ±4,纯黑/纯白才到 8。9 张图 mean|Δ| 2.94 / 4.08 / 4.83 全由此造成。
- **B** `dynamic_mask = min(1, dev*2)`,白(中性)格 `dev=0` → `a_eff=0` → **逐字节不动**。
  74.6% 像素没有水印,9 张恒定 25.38%(= 条纹 50% × 消息区黄占比 50%)。

并按载体亮度分箱验证真实图,与受控曲线一致;再按区域(而非单像素)统计角标,
修正「BR 角标行为不同」的误读 —— **4 个角标 Δ 取值完全相同**,
唯一差别是改动率(20.9–32.6%),由 45° 条纹相位 + BR 压着定位块 #6 决定。

## 融合公式(所有脚本共用)

```python
out = c·(1 − a_eff) + wm·a_eff
a_eff = alpha · min(1, dev*2),   dev = max|wm − 255| / 255
```

模板每像素只有两种值:**黄** (B=0,G=255,R=255) = 信号,**白** (255,255,255) = 中性。
G/R 恒 255,B 承载信号。`alpha = 0.032` → 理论上限 `α×255 = 8.16`,实测 `max|Δ| = 8`,
**零裁剪零溢出**(`255×(1−α)+255α = 255.0` 恰好饱和)。

## 运行

```bash
cd tools
python gen_real_capture_v2.py      # 生成 9 张 -> ../vis/real_capture/
python verify_and_detect_v2.py     # 校验 + vv2 检测
python verify_tpl_equiv.py         # 模板等效性
python qa_wm_effect.py             # 效果 QA
python why_diff.py                 # 根因受控实验
```

Python 环境需要 `numpy` / `opencv-python`;`verify_and_detect_v2.py` 另需 `torch` + `ultralytics`。
