# v2 检测器设计：用周期先验直接读出间隔

> v1 只做了"找 6 个定位块"。v2 的目标变了：**找到水印模板在图中的间隔（pitch）**，
> 而不是逐个特征定位。本文定三件事：**观测尺寸**、**周期先验怎么用**、**多尺度框怎么直接给出尺寸**。
>
> 参考实现已克隆到 `v2/deps/`（ultralytics / yolov12 / yolov13 / yolov10 / RT-DETR）。

---

## 0. 一句话结论

| 决策 | 选择 | 理由（本文给出量化） |
|---|---|---|
| **观测尺寸** | **小块 160×135**（模板像素） | 单实例 SNR=20（σ=30）/ 10（σ=60）；恰好是原子重复单元 |
| **检测目标** | 小块本身，**1 类** `tile` | 像素 SNR=0.1 不可用；符号 ID **不学习**，后处理匹配滤波（§12.4） |
| **输入分辨率** | **原生像素密度**（不 downscale） | 4px 条纹是**渲染像素周期**，任何缩放都混叠；裁剪可以，缩放不行（§12.2） |
| **尺寸从哪来** | **两档**：框宽给粗尺度（~3%），**框中心格点拟合给精密间距**（~0.02%） | 框宽当不了尺子——IoU 对 2.5% 尺寸偏差只掉到 0.95，训练不约束宽度（§5） |
| **周期先验怎么用** | **写进标签**，不写进网络 | 96 个目标本身就是"固定间距的相似弱信号"，证据在逐像素相同的拷贝上相干累积（§11.4） |
| **网络改动** | **零** | 标准 `yolov8n` + 原生 `Detect`，不移植 HyperACE / AAttn / 自定义头（§9） |
| **模板排布** | `M1M2 M1M2 M1M2 / M3M4…` 交替行 | 周期检验的最小正周期唯一；v1 是交错格，存在半周期歧义 |
| **增广** | `hsv=0 scale=0 fliplr=0`，噪声走生成期 | ultralytics 默认增广会**抹掉** Δ≤8 的水印、撕碎 lattice（§12.3） |
| **主指标** | **pitch 相对误差 ≤0.5%**（格点法），不是 mAP | v2 的产出是"间隔"和"ID"，mAP 只是门禁（§13） |

## 1. 模板的三级几何

```
屏幕 1920 × 1080
 └─ 块  320 × 270    4 行 × 6 列 = 24 块          （v1 文档的"块"）
     └─ 小块 160 × 135   8 行 × 12 列 = 96 小块    ★ 原子重复单元 / 观测尺寸
         └─ 格  20 × 16.875   8×8 = 64 格         （一个 RS 符号 = 一个码字）
```

- **小块** = 一个 GF(16) 符号的码字（`CODEWORD_CELL_MASKS[symbol]`，8×8 bit 矩阵）
- 一个**块** = 2×2 小块 = 一个 message 的 4 个符号
- 全屏 96 小块 = 24 块 × 4 符号 = 16 符号序列铺 6 遍（冗余）

**回字形定位图案只占一个小块**（160×135），所以 v1 的 GT 单位本来就是小块，v2 沿用。

## 2. 观测尺寸：为什么是 160×135

用户的判断是对的——**周期性在像素级就成立**，但"周期性成立"不等于"像素可检测"。
把像素当目标不行，要选一个合适的观测窗口。量化如下。

匹配滤波 SNR：`SNR = α·255 · sqrt(N_written) / σ`，`α·255 = 8.16`（只在 B 通道），
`N_written ≈ 0.25 · W · H`（45° 条纹占 50%，黄格占约 50%）。

| 观测窗口（模板 px） | 是什么 | N_written | SNR@σ=30 | SNR@σ=60 | 判定 |
|---|---|---|---|---|---|
| 1×1 | 像素 | 0 | 0.1 | 0.1 | **不可用** |
| 8×7 | 一格 | 14 | 0.5 | 0.2 | **不可用** |
| 40×34 | 4×4 格 | 340 | 2.5 | 1.3 | 勉强 |
| 80×67 | 半个小块 | 1350 | 10.0 | 5.0 | 可用 |
| **160×135** | **小块** | **5400** | **20.0** | **10.0** | **安全** |
| 320×270 | 块（4 小块） | 21600 | 40.0 | 20.0 | 安全 |
| 640×540 | 超块（16 小块） | 86400 | 80.0 | 40.0 | 安全 |

重噪声（σ=60）下单实例要 SNR≥5，需要窗口面积 ≥5407 px（约 74×74）。
**40×34 在重噪声下不够；160×135 够。**

### 为什么不再往大走

| | 小块 160×135 | 块 320×270 | 超块 640×540 |
|---|---|---|---|
| s=1 时实例数 | **96** | 24 | 6 |
| s=2.2 时实例数 | **19.8** | 4.9 | **1.2 ← 太少** |
| 是否原子单元 | **是** | 否 | 否 |
| 框宽含义 | **= 一个 pitch** | = 2 个 pitch | = 4 个 pitch |

**大窗口的实例数随 s 增大掉得太快**，s=2.2 时超块只剩 1 个，没法投票。
小块在全尺度区间都有足够实例（600 → 19.8），且**一个框宽就是一个 pitch**。

> 关键区分：**目标尺寸 ≠ 感受野尺寸**。网络可以整合 ≥160×135 的感受野，
> 仍然只输出一个小块的框。"像素当目标不好"是对的；"像素当证据"没问题。

## 3. 模板排布：v2 让周期检验有唯一最小正周期

v2 块级排布（用户的方案）：

```
行0:  M1 M2 M1 M2 M1 M2
行1:  M3 M4 M3 M4 M3 M4
行2:  M1 M2 M1 M2 M1 M2
行3:  M3 M4 M3 M4 M3 M4
```

在**小块级**（8×12）做"固定间隔 → 相同样式"检验（lag 匹配率，1.0 = 完全相同）：

| lag（小块） | 含义 | v1 交错格 | v2 交替行 |
|---|---|---|---|
| (0,4) | 右移 4 小块 = 640 px | 0.000 | **1.000** |
| (4,0) | 下移 4 小块 = 540 px | 1.000 | **1.000** |
| (4,4) | 对角 = 超块周期 | 0.000 | **1.000** |
| (2,2) | 对角半程 | 0.000 | 0.000 |
| (0,2) / (2,0) | 半程 | 0.000 | 0.000 |

**v1 是交错格**：只有 (4,0) 命中，(0,4) 和 (4,4) 全不命中 → 水平周期被错位打破，
检验结果依赖你从哪一行开始，存在**半周期歧义**。

**v2 是矩形格**：(4,0)/(0,4)/(4,4) 三个都是精确不动点，最小正周期唯一。
这是改排布的**可量化理由**，不是美观偏好。

### 两个嵌套的周期

| 层级 | 周期（模板 px） | 检验的是什么 | 强度 |
|---|---|---|---|
| 小块格 | **160 × 135** | "这里有小块" | 弱（所有小块长像） |
| 符号格 | **640 × 540** | "这里有**同符号**的小块" | 强（8×8 掩码完全一致） |

用户的先验在两层都成立。**主 pitch 用第 1 层估（稳），第 2 层做校验/精化（准）。**

## 4. 检测目标：1 类 `codeword`，符号 ID 不学习

### 4.1 为什么不是像素
SNR 0.1，彻底不可用（上表）。

### 4.2 为什么不是 16 类符号

实测 `CODEWORD_CELL_MASKS`（16 个 8×8 掩码）的两个结构性事实：

| 性质 | 实测值 | 后果 |
|---|---|---|
| 每个掩码的黄格数 | **恒等于 32 / 64** | **黄格密度对符号 ID 零信息**——任何"黄占比"特征都无效 |
| 两两 Hamming 距离 | **恒等于 32 格**（min = mean = max） | 等距常重码，没有哪一对特别易混，混淆均匀 |

> 这是等距码的直接推论：16 个符号信息**只存在于 8×8 的排布**，
> 不在密度、不在总能量。条纹写入后每个小块的有效写入像素数也完全相同
> （都是 64 格 × 337.5 px × 50% 条纹 ≈ 10800 px），所以**匹配滤波 SNR 对 16 个符号也完全一样**。
> 想靠"能量/密度"区分符号的路是死的，只能靠高频排布结构。

距离折合 32 格 = 8100–10800 px。表面上可分：

| σ | 两两 SNR（假定载体已知） | 判定 |
|---|---|---|
| 30 | 12.2 | 容易 |
| 60 | 6.1 | 可行 |
| 100 | 3.7 | 勉强 |

**但载体未知**。观测是 `y = (1−α)·c + α·t·255·stripe + n`，逐像素 `c` 自由，
单像素证据为零。符号判别只可能靠**码字格的高频结构**（格距 20×17 px）——
这恰好是自然纹理载体没有的频率。所以 16 类**依赖载体，不能当闸门**。

### 4.3 真正不受载体影响的两个量
- **小块存在性**：160×135 区域内有一致的 8×8 格结构（格距 20×17）
- **小块周期性**：同样的结构每 160×135 px 重复一次

两者都**不需要知道它是哪个符号**。
→ 用户的先验本质是**周期性检验**，不是符号 ID 检验。这就是它稳的原因。

### 4.4 落地
```
主头   : 1 类 codeword  —— 必须，输出 (cx,cy,w,h,conf)，框宽 = 一个 pitch
符号 ID: 不学习          —— 后处理做匹配滤波（16 张掩码已知且恒定，见 §11.5）
```

~~辅助头 : 16 类 symbol~~ —— **放弃**。16 张掩码是**已知常量**（§4.2），
学一个 16 类分类器只会学到载体相关的东西。把格内高通（去掉低频载体）
再对 `CODEWORD_CELL_MASKS` 做匹配滤波是经典检测问题，确定性、无需训练。
学习的部分只做**"找小块 + 读尺寸"**。

#### 解码器：格内条纹对比 + 相位搜索（定死，见 §11.5 展开）

匹配滤波**不是**在像素上直接跟掩码做相关——载体低频会把它淹掉。真正稳的是
**格内"条纹像素 vs 非条纹像素"的局部对比**：

```
h_rc = ( mean(non-stripe) − mean(stripe) ) · n_on        ← 只看 B 通道，8×8 格
黄格  h ≈ +0.032·C > 0          白格  h ≈ 0
条纹相位猜错 ⇒ h **整体变号** (≈ −⅓·α·C)  ← 硬相位判别器
```

信号是**乘性**的（Δ = −α·C_p，只在黄∩条纹上），所以对比度是唯一不依赖载体
绝对亮度的统计量。条纹相位 φ 只有 1 个自由度（`(x+y+Φ) mod 4`，不是两个），
4 个相位搜一遍即可。

符号判决对 16 张掩码做 **±1 相关**：`score_s = Σ SIGN_s(rc)·h_rc`。
±1 已经是最优的——模板 `T_s = 127.5·(1−sign_s)` 对 `sign_s` 是仿射的，
在 `d = α(T−C)` 的线性模型下匹配滤波的充分统计量就是 sign 本身。

**6 份拷贝相干累积**（把 16 维得分向量相加，不做硬投票），SNR × √6 ——
这才是 §4.3 里"周期性"能换来检测增益的地方。

## 5. 尺寸从哪来：框宽给粗尺度，格点给精密间距

**框宽不能当尺子。** 这是两件事，必须分开：

| | 粗尺度 `s_coarse` | 精密间距 `pitch` |
|---|---|---|
| 从哪来 | 框宽 `w/160` 的稳健均值 | **框中心的格点最小二乘** |
| 用途 | 决定用哪层 FPN、归一化、初值 | **间隔读数、相位/原点、解码对齐** |
| 精度 | ~2–5%，够用 | ~0.02%，远超 0.5% 指标 |
| 性质 | 检测的副产品 | **格点拟合的输出** |

### 为什么框宽不行（三条，全部实测）

**① 训练损失根本不约束框宽。** 中心对齐时尺寸偏差与 IoU 的关系：

| 尺寸偏差 | 预测框 | IoU | CIoU 损失 |
|---|---|---|---|
| 1.0% | 161.6×136.3 | 0.980 | 0.020 |
| **2.5%** | **164.0×138.4** | **0.952** | **0.048** |
| 5.0% | 168.0×141.8 | 0.907 | 0.093 |
| 20% | 192.0×162.0 | 0.694 | 0.306 |

2.5% 的尺寸偏差 IoU 仍有 0.95；**mAP@0.5 的门槛是 IoU 0.5，容得下 20% 尺寸误差**。
损失面在这里几乎是平的，网络没有任何理由把框宽学到 0.5%。

**② 框宽回归有系统偏差，而偏差对平均免疫不了。** DFL（`reg_max=16`，见
`deps/ultralytics/.../block.py:60`）输出的是 16 个 bin 的 softmax 期望，**值是连续的**，
亚 bin 精度在原理上可行——但学到的框宽会**向训练集的尺寸先验收缩**。
取 96 个框的稳健均值只能压随机误差，**压不掉偏差**。

**③ 实测：框宽法对 0.5% 间距差几乎分辨不出，格点法轻松分辨。**
2000 次蒙特卡洛，96 个框，s=1，看 `|Δs|/s ≤ 0.5%` 的达标率：

| σ中心 | σ框宽 | 框宽系统偏差 | 框宽法误差 | 格点法误差 | 框宽达标 | 格点达标 |
|---|---|---|---|---|---|---|
| 1.0 | 2.0 | 0 px | 0.11% | 0.013% | 99.8% | **100%** |
| 1.0 | 2.0 | **4 px** | **2.50%** | 0.013% | **0.0%** | **100%** |
| 2.0 | 5.0 | 0 px | 0.26% | 0.025% | 79.5% | **100%** |
| 2.0 | 5.0 | **4 px** | **4.97%** | 0.025% | **0.0%** | **100%** |
| 3.0 | 8.0 | 8 px | 5.01% | 0.039% | **0.0%** | **100%** |

**4 px = 2.5% 的框宽偏差就把框宽法彻底打死**（达标率 0%），而偏差是一定会有的。
格点法对偏差免疫，因为它量的是**中心之间的间距**，不是框的大小。

区分 `s` 与 `s×1.005` 的可分辨度 `d'`（d'≥2 才算可区分）：

| σ中心 | σ框宽 | 偏差 | 框宽 d' | 格点 d' |
|---|---|---|---|---|
| 1.0 | 2.0 | 0 px | 3.16 | **26.6** |
| 2.0 | 5.0 | 0 px | 1.36 ← 不可区分 | **12.9** |
| 2.0 | 5.0 | 4 px | 1.29 ← 不可区分 | **13.1** |

**答案：框宽不能区别细微间距，格点中心能，快 10–40 倍。**

### 格点法为什么这么强

96 个中心落在 `(tx,ty) + s·(160j, 135k)` 上，拟合 4 个参数 (s, θ, tx, ty)。
一维情况下 `x_i = a·k_i + b + ε_i`，最小二乘给出
`σ_a = σ_c·√12 / (M·√N)`（M=周期数，N=点数）。

| | 数值 |
|---|---|
| σ_c（中心定位误差） | 1–2 px |
| N | 96 |
| M | 12（横跨 12 个码字） |
| **σ_a** | **0.03 px** |
| **相对 pitch（160 px）** | **0.02%** |

格点法的**基线是整屏宽度**（12 个周期），框宽法的基线只有 1 个框——这就是差距的来源。
而且 0.5% 的间距差累积 12 个周期就是 9.6 px ≈ 10σ_c，是**相位漂移**，不是 0.8 px 的宽度差。

### 分工（定死）

```
YOLO 只负责一件事：把 96 个码字块找出来 → 框中心 + 粗尺度
    ↓
确定性几何负责精密测量（纯后处理，不学习）：
    lattice 拟合 (s, θ, tx, ty)   ← ★ 间距从这读出
    ↓  可选：对每个中心做一次格内互相关精修，σ_c 从 2px → 0.2px，格点误差再降 10×
    origin/phase → 逐码字 8×8 格 → 16 张掩码匹配滤波 → 符号
    ↓
RS(15,5) 解码 → ID
```

**网络不被要求当尺子，只被要求当探测器。** 这比"让框宽兼任间距读数"更符合
"少做网络层创新"的原则——精密测量走确定性算法，可靠、可测、可调。

### "多锚点直接找到尺寸"仍然成立

你原话的目标（不搜尺度、直接得到尺寸）没有被推翻，只是**分工**变了：

| 你的说法 | 在 anchor-free YOLO 里的对应物 | 谁来用 |
|---|---|---|
| 多锚点 | FPN P3/P4/P5（stride 8/16/32），每层管一段尺寸区间 | 网络自己 |
| 直接找到尺寸 | DFL 16 bin 期望 = 框宽，**回归连续量**，不是分类 | 网络自己 → 粗尺度 |
| 不搜索尺寸 | 一次前向，不建图像金字塔、不缩模板、不滑窗 | — |
| **（补充）读出间距** | **框中心的格点拟合** | **后处理，精密读数** |

DFL 的 16 个 bin 跨度是 1 个 stride（P3 上 1 bin = 8 px），bin 间距远大于 0.5% 间距差——
这正是框宽当不了尺子的结构性原因。格点拟合用的是**跨 12 个周期的基线**，不受 bin 宽度限制。

### 输入分辨率仍然要原生

| 输入分辨率 | s=1 时小块 | 中心 1px 误差 → 格点 pitch 误差 |
|---|---|---|
| 640 | 53×45 | 0.23% |
| 1280 | 107×90 | 0.10% |
| **1920** | **160×135** | **0.07%** |

（N=96, M=12, σ_c=1px；s 不变时格点误差随分辨率线性改善，因为基线变长。）
但更要紧的仍是 §6：**4px 条纹不能混叠**，这是硬约束。

## 6. 输入分辨率：必须原生 1920（硬约束）

| imgsz | scale | 格距 px | 小块 px | 条纹周期 px | 1px→ds | 混叠？ |
|---|---|---|---|---|---|---|
| 640 | 0.333 | 6.7×5.6 | 53×45 | **1.33** | 0.0188 | **是** |
| 960 | 0.500 | 10.0×8.4 | 80×68 | 2.00 | 0.0125 | **是** |
| 1280 | 0.667 | 13.3×11.2 | 107×90 | 2.67 | 0.0094 | 否 |
| **1920** | **1.000** | **20.0×16.9** | **160×135** | **4.00** | **0.0063** | 否 |

- **45° 条纹（周期 4 px）是写入掩码**，640 下变 1.33 px → 被任何 resize 摧毁
- **8×8 码字格（格距 20×17 px）是信息载体**，640 下缩到 6.7×5.6 px → 勉强可辨
- 也和仓库既有规则一致：**载体图绝不 resize**

→ v2 训练/推理都在 **原生 1920**，或按原生分辨率裁剪的小图（`SCALE_MODE=pad_native`）。
v1 的 `imgsz=640` 是为了让 yolov8n 跑得快；v2 **不考虑成本**，按契合度选。

## 7. 周期先验的用法：检测后的格点共识

这是 v2 相对 v1 的**真正增益点**。

v1 的失败模式（`docs/locator_detection.md` §6.4）：密集图标桌面，图标的直角边缘
与回字形强角点高度相似 → vv1 多报 8 个框、vv2 置信度掉到 0.29 全被阈值卡掉。
**根因：v1 的先验只是"6 个固定网格位置"，没有用上周期性。**

v2 的做法：检测出的框集合 `{(cx_i, cy_i, w_i, h_i, conf_i)}`，在 4 参数族上做 RANSAC：

```
H:  存在 (s, θ, tx, ty)，使得多数框落在
    (cx, cy) = (tx, ty) + s·R(θ)·(160·j, 135·k)   , j,k ∈ ℤ

inlier  = 真小块          outlier = 误报（图标）
```

孤立的图标可能触发一次检测，但**它的邻居不会恰好落在 pitch 上**。
96 个真小块互相印证，一个图标印证不了任何东西。

**这正是用户的先验被算法化**："固定间隔的特征呈现出相同的样式" → 格点共识内点。

### 两个尺度的短板不同，但格点拟合全程够用

| | 小 s（0.4–0.8） | 大 s（1.5–2.2） |
|---|---|---|
| 全屏码字数 | 600 – 170 | 42 – 20 |
| 周期自相似强度 | **强**（重复多） | 弱 |
| 主要短板 | 目标小，**召回** | 实例少，**格点点数** |
| 格点 pitch 误差（σ_c=2px） | ~0.02% | ~0.08% |
| 主要靠 | 格点共识（点极多） | 框中心够准 + 基线仍跨 5+ 周期 |

两端都远优于 0.5% 指标。短板不同但都够——不需要为尺度分段换机制。

### 格点共识的评分：三个必须防的混淆

共识 = 数内点。但**"内点最多"本身不足以定出间距**，下面三种混淆的内点数
都能压过真解。全部实测踩过，逐条记下来：

**① 1/m 倍间距 —— 内点数一分不少。** 真点在真格点上，取 1/m 倍间距时
**每一点照样落在格线上**（真间距 = m × 拟合间距），内点数甚至更多（误报还会
补到中间线上白送一个）。拆它要看**格线占用率**（`_line_occupancy`）：
`用了几条线 / 跨度内有几条线`。真解 ≈ 1，1/m 倍间距 ≈ 1/m。
评分 = `内点数 × occ_j × occ_k`。

> 走过的弯路：奇偶混合度只能拆 m=2（1,4,7,10 的奇偶照样交替）；
> 最小步长怕**单个**误报补线（一个误报把 min-gap 从 3 塌成 1，白送一个内点）；
> 二维"内点数/包围盒格位数"方向是**反的**（稀疏观测下真解 20/96 = 0.21，
> 半间距反而缩包围盒拿到 0.83）。逐轴各算一次再相乘才对，稀疏观测下真解照样 ≈ 1。

**② 旋转格点的投影混淆 —— 尺度先验才能拆。** 160×135 的格点整体转 φ 角后，
它的 x 投影落在间距 `135·sin φ` 的细格线上，**每一个点都严丝合缝**。实测
φ≈9.7° 时细间距 22.5px、89 内点，压过真解的 78。这是纯数据分辨不了的，
必须用尺度先验。而 ±6° 的 θ 搜索范围内这个混淆间距最大只有
`135·sin6° ≈ 14px` ≪ `0.35·hint` —— **量程门槛**（不是罚分）一卡，整族混淆
一起出局。罚分形式不行：罚轻了拦不住 89 vs 78，罚重了又会在 hint 偏小时
把真解一起拦掉。门槛只要求"同一个量级"，对 hint 精度不敏感。

**③ 间距候选表不能被 hint 锁死。** hint 一旦偏掉（误报簇更大、尺度被小框
拖走），只按 hint 生成候选会把真间距整个锁死在表外。两个配套措施：
`majority_size` 按**覆盖面积**取尺寸主簇（不是个数 —— 20 真 + 30 个 30×30
误报时个数主簇是误报）；`_pitch_candidates` **永远**并入无 hint 的阈值扫掠，
靠上面的评分裁决。

外加两条工程细节，不守会静默出错：

* **簇心间距取众数，不取中位数。** 误报落进两条真列之间会把一条真列间距劈成
  两个碎片，中位数被碎片带走（12 列 + 8 误报实测给 209.8px，真值 216，
  **216 一次都没进候选表**）。众数只认"反复出现的那个间距"。
* **`_fit_once` 的掩码必须与参数配套**，精修完重算掩码；精修步拒绝非正间距
  （否则 `px→0` 自激：内点全落在同一格线时回归回出 px=0，下一轮每点残差恒 ≈ 0、
  全体变内点，再回归出莫名其妙的间距）。

## 8. 密集检测下 NMS 是否是问题

96 个小块**铺满整屏、无间隙**，但 NMS 不会误杀邻居：

两个相邻 160×135 框各外扩 2px（共享边）：
`IoU = 540 / (22194 + 22194 − 540) ≈ 0.012`，远低于 NMS 阈值 0.7。

真正要处理的是**同一个小块的重复预测**，这正是 NMS 的本职。
但注意：**imgsz=640 时小块只有 21×18 px，密度上来了，NMS 才会出问题** ——
又一条支持原生 1920 的理由。

## 11. 检测逻辑：把"固定间距的相似特征"当成检测目标

### 11.1 模板上的"固定间距"到底是什么

v2 排布：block 4×6，每个 block = 2×2 码字 = 320×270 px。
以 id=123456 的真实符号格为例（每个方格 = 一个码字 = 160×135 px = 8×8 个 20×16.9 px 格）：

```
              640 px  =  2 block  =  4 码字
        ◄───────────────────────────────►
   ┌────────┬────────┬────────┬────────┬────────┬────────┐ ▲
   │ 3 A    │ F 8    │ 3 A    │ F 8    │ 3 A    │ F 8    │ │
   │ 9 7    │ 6 D    │ 9 7    │ 6 D    │ 9 7    │ 6 D    │ │ 540 px
   ├────────┼────────┼────────┼────────┼────────┼────────┤ │ = 2 block
   │ C 0    │ 2 1    │ C 0    │ 2 1    │ C 0    │ 2 1    │ │
   │ B 4    │ E 0    │ B 4    │ E 0    │ B 4    │ E 0    │ ▼
   ├────────┼────────┼────────┼────────┼────────┼────────┤
   │ 3 A    │ F 8    │ 3 A    │ F 8    │ 3 A    │ F 8    │
   │ 9 7    │ 6 D    │ 9 7    │ 6 D    │ 9 7    │ 6 D    │
   ├────────┼────────┼────────┼────────┼────────┼────────┤
   │ C 0    │ 2 1    │ C 0    │ 2 1    │ C 0    │ 2 1    │
   │ B 4    │ E 0    │ B 4    │ E 0    │ B 4    │ E 0    │
   └────────┴────────┴────────┴────────┴────────┴────────┘
     M1       M2       M1       M2       M1       M2
     M3       M4       M3       M4       M3       M4
```

**逐像素完全相同的组：**

| 粒度 | 一组是什么 | 组数 | 组内间距 |
|---|---|---|---|
| **M 块** | 6 份 M1（= `3A/97` 这个 2×2）**逐像素相同** | 4 组（M1/M2/M3/M4） | **(640, 540) px** |
| **码字** | 同一序列槽位的 6 份拷贝（如 6 个 `3`） | 16 组 | **(640, 540) px** |
| **像素** | M1 内同一像素位置的 6 个像素 | **320×270 = 86400 组** | (640, 540) px |

> 按**符号值**聚合会少一点：id=123456 的 16 槽里符号 0 占了两槽，只有 15 个不同符号值，
> 符号 0 有 12 份拷贝而非 6 份。槽位粒度恒为 16 组、每组 6 份，不依赖 ID。

> **"组数 = 每个 M1 块的像素个数"** 就是最后一行：像素粒度下确实是 86400 组。
> 但像素当目标不可行（§2：SNR=0.1），所以要挑一个合适的最小检测单元。

### 11.2 最小检测单元 = 码字 = 1/4 个 M 块 = 160×135 px

**采纳这个选择。** 各粒度对比：

| 单元 | 尺寸 (s=1) | 全屏个数 | 一个框宽 = | 判定 |
|---|---|---|---|---|
| 像素 | 1×1 | 207 万 | — | SNR 0.1，不可用 |
| 格 (cell) | 20×16.9 | 6144 | — | SNR 0.5，不可用 |
| **码字** ★ | **160×135** | **96** | **一个码字 pitch** | **SNR 20 / 10，可用** |
| M 块 | 320×270 | 24 | 2 个 pitch | 可用，但 s=2.2 时只剩 5 个 |
| 超块 | 640×540 | 6 | 4 个 pitch | s=2.2 时只剩 1 个，没法投票 |

码字是**原子单元**：一个框宽正好一个 pitch，96 个实例在全尺度都够投票（§2、§5）。

### 11.3 检测 = 标准 YOLO 1 类检测

```
待检测图  →  yolov8n (1 类 `codeword`)  →  N 个框 (cx, cy, w, h, conf)
```

**没有任何网络改动。** 就是 v1 那套 `model.train` / `model.predict`，只改 `names`。

**间距从框中心的格点读出来，不搜索：**

```
每个框  →  s_i = w_i / 160                 ← 粗尺度（~3%），够定层/归一化
N 个框中心 → lattice 最小二乘 (s, θ, tx, ty)  ★ 精密间距从这读出（~0.02%）
间隔     = (160·s, 135·s)
同符号间距 = (640·s, 540·s) = 4 × 间隔       ← M1 六份拷贝之间的间距
```

**框宽不能当尺子**（§5 有实测）：IoU 对 2.5% 尺寸偏差只掉到 0.95，CIoU 损失面平坦，
网络没有理由把框宽学到 0.5%；而且框宽回归有系统偏差，取均值压不掉。
框**中心**之间跨 12 个周期的基线才够长。0.5% 的间距差累积 12 周期 = 9.6 px ≈ 10σ_c，
是相位漂移，框宽法 d'≈1.3（分辨不出），格点法 d'≈13（轻松分辨）。

这就是"借助 yolo 的多锚点直接找到尺寸"的全部含义：

| 你的说法 | YOLO 里的对应物 |
|---|---|
| 多锚点 | FPN P3/P4/P5（stride 8/16/32），每层管一段尺寸区间 |
| 直接找到尺寸 | DFL 16 bin 的期望 = 框宽，**回归连续量**，不是分类 |
| 不搜索尺寸 | 一次前向，不建图像金字塔、不缩模板、不滑窗 |

### 11.4 先验用在哪：写进标签，不写进网络

这是上一版搞错的地方。先验**不需要** HyperACE 之类的网络结构来承载——

**96 个检测目标本身就是"固定间距排布的相似弱信号"。**
训练时要求网络把 96 个全检出来，网络就必须对这个重复的弱信号产生响应。
先验被编码进**标签的几何排布**，不是编码进网络结构。

更关键的是：M1 的 6 份拷贝**逐像素相同** ⇒ 同一个滤波器同时匹配 6 份 ⇒
证据在 6 份上**相干累积**（SNR × √6）。这正是"固定间距呈现相似弱信号"
之所以能被检出的物理原因。标准 YOLO 检测头天然做到这件事，不需要额外结构。

### 11.5 端到端

```
待检测图（原生分辨率）
  → yolov8n / yolov12n, 1 类 `codeword`          ← 标准 YOLO，零改动
  → N 个码字框（中心 + 粗尺度）
  → majority_size：按**覆盖面积**取尺寸主簇 → pitch_hint
  → lattice.fit_lattice (s, θ, tx, ty)           ★ 精密间距从这读出（§5）
  → interval = (160s, 135s)；origin = (tx, ty)
  → [可选] 每个中心格内互相关精修，σ_c 2px→0.2px
  → collect_codewords：内点框 → 每个格位切一个码字 patch
  → decode_patches：4 条纹相位 × 16 原点偏移 = **64 假设**
  → RS(15,5) 解码 → watermark ID
```

lattice 拟合是**主测量手段**，不是可选装饰——框宽给不出 0.5% 的间距（§5）。
它同时干两件事：读出间距、剔除孤立误报（共识内点）。
纯几何、不学习、不改网络。

#### 解码器（`lattice.decode_patches`，§4.4 的展开）

```
每个码字 patch（固定整数窗 round(160s)×round(135s)，按比例切 8×8 格）
  → h_rc = (mean(non-stripe) − mean(stripe))·n_on        ← 格内条纹对比，B 通道
  → codeword_scores → (16,) 维得分  score_s = Σ SIGN_s(rc)·h_rc
  → 同一格位的 6 份拷贝**得分向量相加**（相干累积，不硬投票）
  → align_and_decode_scores：16 个原点偏移逐一试，RS(15,5) 出 ID
```

**64 个假设** = 4 条纹相位 × 16 原点偏移。两者都是整数自由度，穷举即可：

* **条纹相位** 1 个 dof：`φ = (dx+dy) mod 4`。相位猜错时 `h` 整体变号，
  `Σ max(h,0)` 就是不依赖符号的相位判别器。`stripe_offset` = **全局 Φ**，
  与切图原点无关（裁剪 `window = screen − (x0,y0)`，贴装 `window = screen + (x0,y0)`）。
* **原点偏移** 16 种：格点只定相对原点，绝对原点要靠符号序列在 16 个
  `slot_of` 偏移上自洽（`slot_of` 在行列上都是周期 4，负下标也成立）。

#### 两个会静默出错的几何契约

**1) `frame_to_window` 的取景偏移符号。** `dx/dy` = **窗坐标 − 屏坐标**：

| 取景 | 像素映射 | 标签偏移 | `stripe_offset` |
|---|---|---|---|
| 1:1 裁剪 | `out[i,j] = img[y0+i, x0+j]` | `dx = −x0` | `Φ = −(x0+y0)` |
| 贴装 | `canvas[y0+i, x0+j] = img[i,j]` | `dx = +x0` | `Φ = +(x0+y0)` |

这个符号**曾经两条分支都写反过**，框整体偏 2×取景偏移（贴装最大 58px、
裁剪最大 662px）。而图像本身一个像素都没变 —— 只查框数量和图像形状的
自检永远是绿的，只有**把框真拿去格点+解码**才会露馅。所以
`generate_dataset_v2 --selftest` 里有一道"标签几何"硬门槛：用样本自带的框
必须解出 ID。

**2) 解码的码字数下限 `n_codewords ≥ 20`。** `align_and_decode_scores` 把空槽
**强行填成符号 0** 再进 RS（`seq_clean = [0 if s < 0 else s]`），空槽就烧掉了
纠错预算。实测：15 个码字 → 4 个空槽 → 4 个假错误，RS(15,5) t=5 在边缘上，ID
丢；20 个码字 → 0 空槽 → `nfix=0` 直接命中。**真部署抓整屏有全部 96 个码字**，
20 是训练窗裁剪出来的稀疏角，不是算法极限。

### 11.6 为什么这能补 v1 的短板

v1 失败模式（`docs/locator_detection.md` §6.4）：密集图标桌面，图标直角边缘
≈ 回字形强角点 → 多报 8 框、置信度掉到 0.29 被阈值卡掉。

v2 的三道闸，**没有一道是网络结构带来的**：

1. **目标换了**：不是"回字形"，是"一个 8×8 码字格（格距 20×17 px）"——图标没有这种周期性格点
2. **数量对上了**：真图 96 个（s=1），误报凑不出 96 个
3. **间距对上了**：图标邻居不会恰好落在 (160s, 135s) 上

## 12. 训练方案：标准 YOLO 训练

### 12.1 三个数据集，两阶段

```bash
# ── 数据集 ① clean：无噪声 ─────────────────────────────────────────
python watermark_locator/v2/dataset/generate_dataset_v2.py \
    --num_samples 4000 --no_noise \
    --carrier_root /data1/lpl/datasets \
    --output_dir /data1/lpl/datasets_v2/clean --jobs 8

# ── 数据集 ② noisy：对①的**同一张图**加三种噪声 ────────────────────
python watermark_locator/v2/dataset/prepare_noise_from_clean_v2.py \
    --clean_root /data1/lpl/datasets_v2/clean \
    --output_dir /data1/lpl/datasets_v2/noisy

# ── 数据集 ③ cropped：对①∪②各 1:1 裁剪后重框回 1920×1080 ──────────
python watermark_locator/v2/dataset/prepare_crop_aug_v2.py \
    --src_root /data1/lpl/datasets_v2/clean \
    --src_root /data1/lpl/datasets_v2/noisy \
    --output_dir /data1/lpl/datasets_v2/cropped

# ── 写两阶段 data yaml（ultralytics 的 train: 接受 list，不用 hardlink）──
python watermark_locator/v2/dataset/write_stage_yaml.py \
    --clean  /data1/lpl/datasets_v2/clean \
    --noisy  /data1/lpl/datasets_v2/noisy \
    --cropped /data1/lpl/datasets_v2/cropped \
    --out_dir /data1/lpl/datasets_v2

# ── 训练：先 ①+② 打底，再 ③ 微调 ──────────────────────────────────
python watermark_locator/v2/train_yolo.py --config vv1/config.yaml
python watermark_locator/v2/predict_interval.py --weights best.pt --image xxx.png
```

**相对 v1 只改三处**：块级排布（交错格 → 交替行）、末位填充（回字形 → 码字 0）、
GT（6 个定位块 → 96 个码字框）。

三个数据集的分工见 §12.6。生成前**各自 `--selftest` 必须先绿**（含端到端解码
硬门槛，见 §12.6.3），再跑批量。

### 12.2 标签

每图一个 YOLO txt，96 行（s=1 时），`0 cx cy w h` 归一化到输入图：

```
0 0.041667 0.062500 0.083333 0.125000
0 0.125000 0.062500 0.083333 0.125000
...   ← 96 个码字，行优先
```

外加 sidecar JSON（**不进损失**，只用于读间隔和评估）：

```json
{"s": 1.0, "interval_px": [160, 135], "symbol_interval_px": [640, 540],
 "symbols": ["3","A","F","8","9","7","6","D", "...96 个，行优先"]}
```

### 12.3 两个必须守住的

| 约束 | 为什么 | 怎么做 |
|---|---|---|
| **输入不能下采样** | 条纹周期 4 px 是**渲染像素周期**，下采样就混叠 | `imgsz` ≥ 图像短边，或用原生密度裁窗 |
| **增广不能毁水印** | 水印 Δ≤8/255 ≈ 3% | 见下表黑名单 |

其余一律**用 ultralytics 默认**，不折腾。

| 参数 | 默认 | v2 | 原因 |
|---|---|---|---|
| `hsv_h/s/v` | .015 / .7 / .4 | **0 / 0 / 0** | `hsv_v=0.4` 是 ±40% 亮度，比水印大一个量级，直接抹掉 |
| `scale` | 0.5 | **0** | 尺度由生成时的渲染分辨率控制（12.4），这里再缩会重采样条纹 |
| `fliplr` | 0.5 | **0** | 镜像翻转 lattice，解码时不知道翻没翻 → ID 解不出 |
| 其余 `translate` / `mosaic` / … | 默认 | **默认** | 不折腾 |

噪声（wechat JPEG / tile_crop / pimog 屏摄）在**生成期物理施加**，不靠 ultralytics 像素增广。

### 12.4 尺度覆盖：数据侧解决，不是网络侧

要覆盖的 s 来自**屏幕分辨率不同**（模板铺满整屏 → 码字 = `W/12`）：

| 屏幕宽 W | s | 码字 px | 格距 px | 条纹 px |
|---|---|---|---|---|
| 1280 | 0.67 | 107×90 | 13.3×11.3 | **4** |
| **1920** | **1.0** | **160×135** | **20×16.9** | **4** |
| 2560 | 1.33 | 213×180 | 26.7×22.5 | **4** |

**条纹恒 4 px，码字随 s 变** —— 所以尺度要用"**按目标分辨率原生渲染模板**"来模拟，
**不能用 downscale**（那会把条纹一起缩掉）。载体与模板同分辨率、1:1 裁剪/平铺拼装，**不 resize**。

s ∈ [0.5, 2.2] 就在生成器里渲染 W ∈ [960, 4224]，各占一定比例。

### 12.5 算力

| 项 | 值 | 依据 |
|---|---|---|
| `imgsz` | **1920** | 条纹 4 px 不能混叠；ultralytics pad 到 1920×1920，不缩放 |
| batch | 8 | 23 GB 卡；有效 batch 仍 64（`nbs` 累积），**lr 不随 batch 改** |
| workers | 32 | 瓶颈是 PNG 解码 CPU，不是盘 |
| 并发 | **一次只跑一个** | `/data1` 是 IO 瓶颈 |

省算力可用原生密度 1280×720 裁窗（码字仍 160×135、条纹仍 4 px），算力 1/2.25。

### 12.6 三个数据集的分工，以及两个必须绕开的坑

#### 12.6.1 分工

| 数据集 | 内容 | 规模(现值) | 作用 |
|---|---|---|---|
| ① `clean` | 无噪声 | 4000 | 干净水印，教"信号长什么样" |
| ② `noisy` | ①的同一张图加 3 噪声：`wechat` / `pimog` / `pimog_wechat` | 12000 = 4000×3 | 采集鲁棒性 |
| ③ `cropped` | ①∪② 各 1:1 裁剪 + 重框回 1920×1080 | 16000 = (4000+12000) | 打破格点位置先验，学会残缺码字 |

②与①是**同 stem 配对**（`train_000123` / `train_000123_wechat` / `_pimog` /
`_pimog_wechat`）：同一载体 + 同一水印 + 同一取景，**噪声是唯一变量**。

训练 = 先 ①+② 合起来打底（`stage1.yaml` 的 `train:` 是 list，两棵树并列），
再用 ③ 微调（`stage2.yaml`）。`train_yolo.py` 的 `stages` 会把 stage1 的
`best.pt` 当 stage2 的初始权重（实测 `yolo_finetune/args.yaml` 的 `model:` 就是
`yolo_base/weights/best.pt`）。微调 lr 取打底的 1/5（0.01 → 0.002），
有效 batch 恒 64（`nbs`），**lr 不随 batch 动**。

③为什么不重新生成水印：裁剪是纯几何后处理，重新渲染会引入第二套随机数，
①②③就不再同 stem 配对了。`prepare_crop_aug_v2.py` 只读 PNG + txt，不动模板。

#### 12.6.2 坑一：裁剪图**不能按原生尺寸存盘**，必须生成时就贴回 1920×1080

ultralytics `BaseDataset.load_image` 把长边**无条件**缩到 `imgsz`：

```python
r = self.imgsz / max(h, w)          # 没有 min(r, 1.0)
```

这一步跑在 `LetterBox(scaleup=False)` **之前**，所以 `scaleup=False` 根本拦不住。
实测（8.4.157, imgsz=1920，train/val × rect 真假 × batch 1/3，8 种组合全一致）：

| 源图 | 张量 | 亮块(真值 160×135) | 尺度 |
|---|---|---|---|
| 1920×1080 | 1952×1568 | 160×135 | **1.000** ✓ |
| 961×600 | 1952×1568 | 320×270 | **2.000** ✗ |
| 500×400 | 1952×1568 | 614×519 | **3.840** ✗ |

一旦被缩放，4 px 条纹周期（**渲染像素周期**）被双线性重采样成 4k px 的平滑波，
160s×135s 这把像素间距尺也没了 —— 正是 §12.4 严禁的那件事。

v1 靠自己 loader 里的 `SCALE_MODE=pad_native` 在读入时补；v2 走 ultralytics 的
YOLO yaml、没有自己的 loader，所以**pad 只能在生成时做**：
`prepare_crop_aug_v2.crop_to_window()` 把裁剪片 1:1 贴进一张 1920×1080 载体画布
（`_carrier_canvas`，同 §12.4 的"绝不 resize"），全程零重采样。

> 顺带记一笔部署侧的推论：**真实截屏若不是 1920×1080，推理前也要同样补回窗**，
> 否则推理时又被 `load_image` 放大，训练/推理尺度就不一致了。
> `predict_interval.detect()` 目前还没做这一步。

#### 12.6.3 坑二：残缺码字必须标 **amodal 全框**，不能标裁剪后的框

裁缺码字的**裁剪框中心是偏的**，会把格点拟合直接拉垮。实测（同一张图、同一裁剪）：

| trial | 含裁缺框 | 仅用完整框 | 渲染真值 |
|---|---|---|---|
| 1 | s=1.230, rms=**101.19** | s=1.35590, rms=**0.27** | 1.35509 |
| 4 | s=1.35590, rms=19.53 | s=1.35590, rms=**0.23** | 1.35509 |

rms 从 0.2 px 劣化到 17~101 px，s 最多偏 9%，ID 当场解不出。RANSAC 的
`tol=3 px` 挡不住：裁缺 30% 的框中心偏 30 px，却仍会被收成内点。

所以标注写**完整的原框**（平移进画布，不裁短）。保留规则要求
**可见宽、高各 ≥ 50%**（= 8×8 格里保住 4×4），于是框中心一定落在可见部分内 ——
既拿到精确中心，YOLO 的正样本格又不会落到载体垫上。附带好处：

* 所有框恒 160s×135s，`majority_size`（间距初值）不被裁剪尺寸污染
* 残缺码字仍是正样本，网络在裁剪边缘不会学成"不响应"
* 完整框超出 1920×1080 画布时**整条丢弃**（不裁短，否则又把偏移引回来），
  计数在 `info['n_out_of_canvas']`

**这不是零代价的**，别把它写成免费：被裁缺的那半个框会盖在**载体垫**上，
框的 **extent（范围）回归目标有一部分落在没有码字的像素上**，是训练噪声。
中心精确（0.27 px）是确定的收益，extent 略脏是确定的代价 —— 相比 rms
0.2→101 这个代价值得付，但它确实存在。真要消掉，得在损失里给 extent
降权或用 ignore 区，那是 §13 之后的事，现在不做。

**`n_out_of_canvas` 是贴装位置的函数，不是裁剪面积比的函数。**
推导很短：**非裁缺框必然放得进画布** —— 完整框在裁剪窗内，`nx0 >= px >= 0`
且 `nx1 <= px+cw <= win_w`。所以出画布**只发生在 amodal 裁缺框**上，
当且仅当贴装位置离画布边缘小于该框"戳出裁剪窗多远"(stick)：
`px < stick_left` 或 `px > (win_w-cw) - stick_right`。
驱动量是**贴装余量 `win - crop`**，面积比只是相关项（宽而矮的小面积裁剪
照样余量小）。实测 stick mean 30.9 px / median 20 / max 133，
出画布占裁缺框 12.8%（25/196），折成保留码字的 **2.4%**。

丢的这批有**选择偏差**：P(丢) ∝ stick，所以被丢的是**戳得最远 = 裁得最狠**
的那些，恰恰是残缺码字里最难、最该学的。`prepare_crop_aug_v2.py` 的
`--keep_amodal_in_canvas` 把贴装收窄到可行区间即可一个不丢（成对实测
16/16 裁剪窗相同、裁缺 205 不变、保留 800→820，多保住的正好是那 20 个）。
代价是贴装分布略偏离边，相位多样性不受影响（相位主要来自裁剪窗位置，
而裁剪窗不因此改变）。**默认关**，因为磁盘上那棵树是默认行为生成的，
重跑必须逐位可复现 —— 已用改前快照硬比过 6/6 逐位一致。
`info['paste_policy']` 记下走的哪条。

另记一条边界：`KEEP_SIDE_RATIO = 0.5` 的 `>=` 是**闭**的 —— 恰好 50% 时
框中心正好压在可见区边界上（框 [0,100]、可见 [50,100]、中心 50），零裕度。
注意这只影响**证据充分性**（网络还看得见多少码字内容），**不影响中心精度** ——
amodal 中心恒等于全框中心，与可见多少无关，这正是写全框的意义。
想留裕度就把 `KEEP_SIDE_RATIO` 提到 0.5+ε；不改也行。

#### 12.6.4 自检的门槛怎么设

**"框数量对 / 图形状对 / 覆盖率对"不能当门槛** —— 标签几何写反时图像一个像素都不变，
这些统计量照样全绿（v1 的 `frame_to_window` 取景偏移符号两条分支都写反时，
自检一路绿灯）。门槛必须是**用产物自带的几何解出语义**：拿写下的标签框当
"完美检测"跑格点拟合 + 解码，要求解出的 `watermark_id` 等于 meta 真值。

但解码本身有数据量下限（16 符号投票 + RS(15,5)）。实测 12 张 × 10 裁剪：

| 可见码字数 | ID 解对 | 拟合 s 误差 <1% |
|---|---|---|
| ≥ 32 | 57/57 (100%) | 57/57 |
| ≥ 16 | 81/82 (99%) | 82/82 |
| ≥ 10 | 84/87 (97%) | 86/87 |
| ≥ 6 | 85/109 (78%) | 96/109 |

所以下限 **`DECODE_FLOOR = 16`** 以上是硬门槛，以下是报告项 —— 否则会把
"裁得太狠"误报成几何错误。注意 **拟合 s 比 ID 稳健得多**（ncw≥12 就 86/86），
所以 s 也要单独设门槛：它才是"像素间距这把尺子没被毁"的直接证据。

#### 12.6.5 "解不出 ID"不等于几何错 —— 解码门槛的分级

§12.6.4 说门槛必须靠解码，但**解不出 ID 有好几种成因，只有一种是几何错**。
不分级就会误报：实测 clean 树 150 张里 6 张解不对，**没有一张是几何问题**。

判级函数是 `predict_interval.judge_decode()`，两个自检共用同一份定义
（不能各写各的，否则同一批数据一个脚本过、另一个不过）：

| verdict | 含义 | 门槛 |
|---|---|---|
| `ok` | 解对了 | — |
| `floor` | `ncw < 16`，16 符号投票 + RS(15,5) 的数据量下限 | WARN |
| `wipe` | 码字够、几何也对，但**解不出** → 载体把 ±8/255 调制抹了 | 见下 |
| `misdecode` | 码字够、几何也对，但**解错**（RS 纠到错码字）| 见下，更严重 |
| `geom` | `s` / `interval_px` 对不上 | **逐张硬 FAIL** |

**为什么几何逐张硬卡、解码看比率：**

* 几何错是**系统性**的 —— 同批塌到 0%，比率门槛一抓一个准
* `wipe` / `misdecode` 是**散发**的 —— 挂一两张，逐张硬卡必误报
* 但解码这道门**不能删**：**偏移符号写反只有解码抓得到**。所有框平移
  2×取景偏移会被 `LatticeFit` 吸进 `tx,ty`，`s` / `rms` / `interval_px`
  照样漂亮。删掉解码门槛 = 把 v1 犯过的那个错重新放进来。

**证据：** `clean/train_000036` —— `ncw=96`、`n_obs` 6-6（16 槽全覆盖）、
`n_empty_slots=0`、`s_err` 0.026%、`rms` 0.35，`id` 仍是 `None`。
96 个码字全读出来了，是**符号读错**不是没读到。同批 `train_000133`
更糟：`ncw=12` 时 RS `nfix=5` 纠出个**错 ID**（535912，真值 50612）
—— 所以"id 不是 None"绝不能当通过，必须和真值比。

**条件化才是消掉载体这个变量的办法**（比再渲一遍便宜得多）：
裁剪后的解码门槛只对"**未裁剪基线本来就解得对**"的样本生效。
基线都解不出 → 那张载体本来就抹调制，裁剪结果不携带几何信息，判 FAIL 是误报；
基线解得对、裁剪后解不对 → 同一载体同一 id，只能赖裁剪。

**三棵树的门槛不一样，别抄错：**

| 树 | 解码门槛 | 理由 |
|---|---|---|
| clean | 批量收集：命中率 ≥95%（`ncw≥16` 的样本里）| 基线就是它自己 |
| noisy | **只作报告**，无命中率门槛 | 加噪的本意就是压低可读性；"加噪后解不出"和"标签同步坏了"在解码层是同一个现象 |
| cropped | 条件化逐张：基线 ok ⇒ 裁后必须 ok | 裁剪不该毁信号 |

noisy 那一行要特别小心：实测同一张 `train_000000`，clean 解得出，
加 **wechat 一项**就解不出（`s_err` 仍 0.004%、`ip_err` 0.029px —— 几何
没坏，是调制被压掉）。所以 noisy 树**不能**用 clean 的 95% 那把尺。
noisy 的刚体平移型标签错误（`_sync_labels_to_warp` 的偏移反号）只能靠
**大批量**验收集的命中率抓，小样本自检的比率没有统计意义 —— 这就是
自检不设比率门槛、批量验收才设的原因。

## 13. 评估协议

v1 看 mAP，但 **mAP 不是 v2 的主指标** —— v2 的产出是"**间隔**"和"**ID**"。

| 指标 | 怎么算 | 门槛 | 说明 |
|---|---|---|---|
| codeword mAP@0.5 | 标准 | ≥ 0.95 | 门禁，不是目标 |
| **pitch 相对误差** | `\|ŝ − s\| / s`，**格点拟合读数** | ≤ 0.5% | **主指标**（框宽读数不进指标） |
| **格点共识检出率** | inlier ≥ 阈值判"有水印" | TPR ≥ 0.99 @ FPR ≤ 0.001 | |
| **密集图标桌面误报率** | v1 痛点集 | FPR ≤ 0.01 | **这是 v2 的存在理由** |
| **ID 解码成功率** | RS(15,5) 解出正确 ID | ≥ 0.95 | 端到端 |
| 工作带 | s 扫 [0.4, 2.2] | 两端不塌 | |
| 符号 ID 准率 | 匹配滤波 | ≥ 0.9 | 辅助，不进闸门 |

s 两端由不同机制扛（§7 的互补性），指标也要拆开看：

| | 小 s（0.4–0.8） | 大 s（1.5–2.2） |
|---|---|---|
| 起主导 | **格点共识** | **框尺寸回归** |
| 主要看 | 检出率 / 误报率 | pitch 误差 |

§5 的蒙特卡洛（框宽 vs 格点，96 框，判 0.5% 达标率与 d'）：

```bash
/data1/lpl/miniconda3/envs/lpl/bin/python - <<'EOF'
import numpy as np
rng = np.random.default_rng(0)
PW, PH, NX, NY = 160, 135, 12, 8
j = np.tile(np.arange(NX), NY); k = np.repeat(np.arange(NY), NX)

def slope(t, u):
    tc, uc = t - t.mean(), u - u.mean()
    return float((tc*uc).sum()/(tc*tc).sum())

def measure(s, sc, sw, bw):
    ox = (j+.5)*PW*s + rng.normal(0, sc, j.size)
    oy = (k+.5)*PH*s + rng.normal(0, sc, k.size)
    w  = PW*s + bw + rng.normal(0, sw, j.size)
    return np.median(w)/PW, (slope(j, ox)/PW + slope(k, oy)/PH)/2

for sc, sw, bw in [(1,2,0), (1,2,4), (2,5,0), (2,5,4), (3,8,8)]:
    a = np.array([measure(1.0, sc, sw, bw) for _ in range(2000)])
    ok = (np.abs(a - 1.0) <= 0.005).mean(axis=0)
    print(f"σc={sc} σw={sw} bias={bw}px  框宽达标 {ok[0]*100:5.1f}%  格点达标 {ok[1]*100:5.1f}%")
EOF
```
